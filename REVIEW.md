# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 73–74) | Always returns `{"status": "ok"}` without pinging MongoDB. If the database is down the probe still returns 200. | Stop MongoDB and call `GET /health` — still returns 200 instead of 503. | Added `db.command("ping")` inside a try/except; raises HTTP 503 on failure. |
| 2 | `create_employee()` (line 79–80) | Race condition: two simultaneous requests for the same `emp_code` both pass the `find_one` check and both insert, producing a duplicate document. No unique index exists. | Send two concurrent `POST /employees` with the same `emp_code`. | Created a unique index on `emp_code` at startup; catch `DuplicateKeyError` and return 409. |
| 3 | `create_employee()` (line 82) | `datetime.now()` is called without `tz=timezone.utc`, producing a naive datetime. PyMongo stores naive datetimes as-is; when read back they look like UTC but are ambiguous. The API spec says instants must be epoch milliseconds; `created_at` would be missing from the response. | `GET /employees` returns `created_at` as a Python dict from MongoDB instead of epoch milliseconds. | Used `datetime.now(tz=timezone.utc)` and added `_serialize_employee()` to convert to epoch milliseconds at the API boundary. |
| 4 | `list_employees()` (line 93) | `skip = page * page_size` — off-by-one. Page 1 should skip 0 records; this skips `page_size` records, so page 1 returns the *second* page of results. | Request `GET /employees?page=1` — first employee is missing. | Changed to `skip = (page - 1) * page_size`. |
| 5 | `list_employees()` (line 94) | `total` is always the count of the full collection, ignoring the `department` filter. Per spec: `total` must count the filtered set. | `GET /employees?department=Engineering` returns `total` = count of all employees, not just Engineering. | Changed to `db.employees.count_documents(q)` where `q` already has the department filter. |
| 6 | `list_employees()` (line 95) | Results are not sorted by `emp_code` ascending. The spec requires this sort order. | Any response with more than one employee will be in arbitrary insertion order. | Added `.sort("emp_code", ASCENDING)` to the cursor. |
| 7 | `punch_in()` (line 102) | `datetime.fromtimestamp(body.punched_at / 1000)` creates a *local-time* naive datetime, not UTC. On a server whose timezone is IST, this misinterprets the epoch value by 5 h 30 min. | Punch in at epoch ms = 1783312500000 (09:55 IST); the stored datetime drifts by 5.5 hours. | Used `datetime.fromtimestamp(ms // 1000, tz=timezone.utc)` (UTC-aware). |
| 8 | `punch_in()` (line 103) | `ts.date()` runs in local server time, not IST. The attendance date is wrong when the server clock's timezone differs from IST. Also, R1 overnight-shift rule is not applied at all. | Server with TZ=UTC: punch in at 20:00 UTC (01:30 IST next day) gives yesterday's date. | Wrote `_attendance_date()` that converts to IST and applies the overnight-shift exception. |
| 9 | `punch_in()` (line 104–105) | Duplicate check is a read-then-insert (TOCTOU): two simultaneous punch-ins pass the `find_one` guard and both insert. | Two concurrent requests for the same `(emp_code, date)` both return 201 and create two records. | Rely solely on the unique compound index `(emp_code, date)` and catch `DuplicateKeyError`. |
| 10 | `compute_late_minutes()` (line 35–37) | `start` is built with `punch_in.replace(hour=…)` which keeps the original timezone info. If `punch_in` is UTC-aware and the shift is IST, the comparison is off by 5.5 hours. Also the logic returns `minutes if minutes > 10` but R2 says "strictly more than 10:00" and `late_minutes` is the floor of total minutes since `shift_start`, not since the grace-period end. | 09:40:01 shift-09:30 should give `late_minutes=10`, but the original returns `10 > 10 → False → 0`. | Rewrote to convert to IST first, compute elapsed seconds, return `floor(elapsed_seconds/60)` when `elapsed_seconds > 600`. |
| 11 | `compute_overtime()` (line 44–47) | `datetime.fromisoformat(date_str)` is a naive date (midnight local time); assigning `tzinfo=IST` to it creates an incorrect offset because the datetime is not actually IST midnight. Also, when `punch_out < shift_end` (left early), `max(0, …)` is applied, but the spec says return 0 only when the value is below 30 min — leaving early is simply 0, which coincidentally works, but returning any positive value < 30 should also be 0. | Punch out at shift_end + 15 min gives `overtime_minutes = 15` instead of 0. | Rewrote to produce a proper IST-aware shift-end datetime (handling overnight shifts on the next calendar day) and apply the ≥30-minute threshold. |
| 12 | `punch_in()` (line 119) | Returns `doc["id"] = str(res.inserted_id)` — the spec says `_id` is internal and must never appear in a response. The correct fields (per `AttendanceRecord`) have no `id` key. | Response body contains `"id": "…ObjectId…"` which is not in the contract. | Removed the `id` field; use `_serialize_record()` which only pops `_id`. |
| 13 | `list_attendance()` (lines 144–146) | Loads the entire collection into memory with `list(db.attendance_logs.find(q))` and sorts/paginates in Python. On 100 k records this is a full table scan and OOM risk. | With 100 k records the endpoint becomes very slow and may exhaust memory. | Push sort and skip/limit into MongoDB; count with `count_documents(q)` using the index. |
| 14 | `list_attendance()` (line 149) | `d["id"] = str(d.pop("_id"))` adds a non-spec `id` field and removes `_id`, but `punch_in`/`punch_out` remain as Python `datetime` objects (not epoch ms). | Punch times returned as datetime strings instead of integers. | Used `_serialize_record()` which converts datetimes to epoch milliseconds and drops `_id`. |
| 15 | No validation on `punched_at` (all punch endpoints) | The spec rejects values that look like seconds (< 100 000 000 000), floats, and out-of-range numbers with 422. The starter has no such check. | Sending `"punched_at": 1783312` (seconds) silently creates a record in 1970. | Added Pydantic `field_validator` that enforces the `[100_000_000_000, 4_102_444_800_000]` range. |
| 16 | No `punch-out`, regularize, or analytics endpoints | Seven of the eleven required endpoints are missing. | Any call to these routes returns 404. | Implemented all missing endpoints. |

## Items inspected and judged **not** to be defects

- **`load_dotenv()` at module level** — acceptable; `python-dotenv` is a stated dependency and real env vars take precedence per the spec.
- **`IST = timezone(timedelta(hours=5, minutes=30))`** — correct constant; Python's `timezone` supports sub-hour offsets.
- **`body.model_dump()` in `create_employee`** — Pydantic v2 API, correct given `pydantic>=2.6` in requirements.
